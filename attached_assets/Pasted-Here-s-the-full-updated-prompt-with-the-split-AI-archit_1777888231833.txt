Add security features to my existing revision app. Do not rebuild or change any existing functionality — only add the following security layers:

1. Rate Limiting — Claude (Question Generation Only)

	•	Claude is used exclusively for question generation
	•	Maximum 400 Claude requests per hour across ALL users combined — not per user
	•	This supports approximately 40 students starting quizzes simultaneously with 10 topics each
	•	Use a global token bucket for Claude requests shared across all users
	•	If the Claude limit is hit, queue the request and retry after a short delay rather than rejecting it immediately
	•	If the queue is full, return a friendly message: “Our question generator is busy right now, please try again in a moment”
	•	Never expose raw Claude API errors to the frontend

2. Rate Limiting — Gemini (All Other Features)

	•	Gemini handles everything except question generation: material processing, answer analysis, summaries, feedback etc.
	•	Maximum 500–1000 Gemini requests per hour globally as a safety net
	•	Maximum 50 Gemini requests per hour per user to prevent individual abuse
	•	Use sliding window algorithm per user
	•	When a user hits their limit return: “You’ve been very busy studying! Take a short break and come back in a moment”

3. Per-User Request Limits (across both AIs combined)

	•	Maximum 20 requests per minute per user across both Claude and Gemini combined
	•	Maximum 150 requests per hour per user across both AIs combined
	•	Maximum 300 requests per day per user across both AIs combined
	•	Each full question cycle uses approximately 3 API calls total (1 Claude + 2 Gemini) so limits are set accordingly — 300 daily requests allows roughly 100 full question cycles per day
	•	Reset daily counts at midnight

4. API Key Security

	•	Store both the Anthropic API key and Gemini API key in environment variables/Replit Secrets
	•	Audit the codebase and remove any hardcoded API keys
	•	Confirm neither API key is ever sent to the frontend under any circumstances
	•	All Claude and Gemini API calls must be made server-side only

5. Input Sanitisation

	•	Add sanitisation to every route that passes user input to either Claude or Gemini
	•	Strip prompt injection patterns (e.g. “ignore previous instructions”, “act as”, “disregard your instructions”)
	•	Escape HTML/Markdown in user messages to prevent XSS
	•	Enforce a hard character/token cap on all user inputs before they reach either API
	•	Sanitise uploaded material before it is passed to either AI — check file type, size, and content

6. Per-User Token Tracking

	•	Log every API call with: user ID, timestamp, which AI was used (Claude/Gemini), input token count, output token count, and which stage of the question cycle it was (material processing / question generation / answer analysis)
	•	Enforce daily caps per user and block further requests if exceeded
	•	Store logs in the existing database — do not create a new one
	•	Reset daily counts at midnight

7. Error Handling

	•	Wrap all Claude and Gemini API calls in try/catch
	•	Never return raw API errors or stack traces to the frontend
	•	Return generic user-friendly error messages instead
	•	Handle 429 rate limit errors from both Claude and Gemini gracefully with a retry after delay
	•	If Claude is unavailable, do not fall back to Gemini for question generation — queue and retry Claude only

8. Upload Security

	•	Validate file type and size before accepting any uploaded material
	•	Reject files that exceed a reasonable size limit
	•	Only allow expected file types (PDF, txt, docx etc.)
	•	Strip any malicious content before passing to either AI

Important: Read the existing code first before making any changes. Preserve all current routes, UI, and functionality exactly as they are.
